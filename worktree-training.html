Chapter 01

What is a Worktree?

A git worktree lets a single repository have multiple working directories, each checked out to a different branch — simultaneously.

◆

No More Branch Switching

Instead of git stash + git checkout, just cd into another directory. Your WIP stays untouched.

●

Shared Object Database

All worktrees share the same .git objects. Creating a new worktree is near-instant and uses minimal extra disk space.

△

True Parallelism

Run builds, tests, and dev servers in separate worktrees at the same time. No waiting. No context-switch tax.

Key Concept

The original directory is the main worktree (created by git init or git clone). Additional directories created via git worktree add are linked worktrees. Each has its own HEAD, index, and working files — but they all share refs, hooks, and objects.

Chapter 02

How It Works Internally

Understanding the plumbing helps you debug issues and appreciate why worktrees are so lightweight.

Architecture: Shared .git, Isolated Working Trees
Main Worktree
/project/.git/
Full object database, refs, hooks, config
.git/worktrees/ stores per-worktree HEAD + index
Worktree A
../auth/
.git file → pointer to main
Worktree B
../payments/
.git file → pointer to main
Worktree C
../bugfix/
.git file → pointer to main

Main worktree owns .git/

Contains the full object database, all refs, hooks, and config. This is the single source of truth.

Linked worktrees get a .git file

A plain text file with one line: gitdir: /project/.git/worktrees/auth — a pointer back to the shared repo.

.git/worktrees/ stores per-tree state

Each linked worktree gets its own HEAD, index, and commondir file inside this directory.

Objects are shared, not copied

A git fetch in any worktree updates all of them. No extra network calls or disk duplication.

Chapter 03

Real-World Use Cases

Worktrees aren't just for multi-agent workflows. Here's where they shine in everyday development.

⧉

Parallel Feature Dev

Work on feature-A and feature-B simultaneously. Each in its own editor window, its own terminal, its own branch.

🔎

Code Review While Coding

Check out a colleague's PR in a separate worktree. Review it without touching your WIP. No stash needed.

⚡

Emergency Hotfixes

Production is down? Create a hotfix worktree from main in 2 seconds. Fix, push, and go back to what you were doing.

⚙

Long-Running Builds

Start a full test suite or build in one worktree. Continue developing in another. Don't wait.

🚀

CI/CD Pipelines

CI can use worktrees to run parallel jobs (lint, test, build) from a single clone — saving network and disk.

🎓

Experimentation

Create a detached HEAD worktree to experiment freely. If it works, branch it. If not, remove it cleanly.

Hotfix workflow example bash 
# Production bug while you're deep in a feature
$ git worktree add -b hotfix/critical-bug ../hotfix main

$ cd ../hotfix
# Fix the bug, commit, push, create PR
$ git commit -am "fix: null check in getUserById"
$ git push -u origin hotfix/critical-bug

# Done? Clean up and go back to your feature
$ cd ../project
$ git worktree remove ../hotfix

Why Agents Need Worktrees

The Problem

When an AI agent modifies files, the working tree is dirty. You cannot start another agent on the same checkout without conflicts. Worktrees give each agent a completely isolated working directory with its own branch, while sharing git history.

Subagent Isolation

How It Works

Claude Code subagents can use worktrees for task isolation. Set isolation: worktree in subagent configuration, or simply ask Claude to "use worktrees for your agents." Each subagent gets its own worktree, automatically cleaned up when done.

Best Practices for Multi-Agent Work

⚖

Task Independence

Only parallelize genuinely independent work. Shared files create "conflict surface area" that requires sequential execution.

🔒

Branch Safety

Each agent commits only to its assigned branch. Restrict force pushes and repo-wide git operations.

📝

Scope via CLAUDE.md

Put a CLAUDE.md in each worktree with task-specific instructions about file scope and branch restrictions.

Chapter 06

Gotchas & Pitfalls

Know these before you get burned. Each one has caught someone on the team (or will).

⚠ Same branch in two worktrees

Git will not allow checking out the same branch in two worktrees. You'll get an error. Use -b to create a new branch, or use --detach for a detached HEAD.

⚠ Never delete worktree folders manually

Always use git worktree remove. Manual deletion leaves stale metadata in .git/worktrees/ that you'll need to clean with git worktree prune.

⚠ Gitignored files don't exist

.env, node_modules/, build artifacts — none are present in new worktrees. Your agent will try to run code with zero dependencies. Use .worktreeinclude or setup scripts.

⚠ Stashes are shared

git stash operates on the shared repository. Stashes created in one worktree are visible in all others. This can cause confusion when multiple people (or agents) stash.

⚠ Port collisions

Multiple dev servers running across worktrees will fight over the same ports. Configure each worktree's dev server to use a unique port.

⚠ Disk space accumulates

While git objects are shared, each worktree gets a full copy of working files plus node_modules and build artifacts. Clean up worktrees promptly with git worktree remove.

✔ origin/HEAD may be stale

Claude Code's --worktree branches from origin/HEAD. If the remote's default branch changed, run git remote set-head origin -a to re-sync.

Creating Worktrees

git worktree add ../feature

Managing Worktrees

git worktree list
List all worktrees with branch + commit
git worktree remove ../feature
Cleanly remove a worktree (must be clean)
git worktree remove -f ../feature
Force remove (dirty or has submodules)
git worktree move ../old ../new
Relocate a worktree directory
git worktree prune
Clean up stale worktree metadata
git worktree prune -n -v
Dry-run: see what would be cleaned

Lock & Repair

git worktree lock --reason "msg" ../wt
Prevent pruning (for portable drives)
git worktree unlock ../wt
Re-enable pruning
git worktree repair
Fix broken links after moving main worktree
